\subsubsection*{Configuration of the protocols}

The behavior of each protocol depends on the values of its parameters.
To configure these parameters in a meaningful way, we choose values previously reported in the literature.
For instance, we use 0.5 seconds as the \textit{hello time} for both \textit{MPR} and \textit{node-degree-based} CDS.
In the case of \textit{ABBA}, we use 0.6 seconds as the maximum waiting time.
Finally, for \textit{ProbFlood} we assign the values $k=$, $\sigma$, and \textit{hello time} = 0.5.

\subsection{Performance Metrics}

\paragraph{\textbf{Saved rebroadcasts}}
is the number of messages that the network do not send thanks to the use of a particular broadcast algorithm.
%
More formally, let $k$ be the number of observed retransmissions required to flood the message $m$ using algorithm $a$; and let $n$ be the number of nodes in the network; then, we saved $n - k$ rebroadcast by using $a$ instead of \textit{simple flooding}.
%
This metric is useful to measure the efficiency in terms of both network and energy usage. 

\paragraph{\textbf{Duplicated messages}}
is the number of extra times a message is received.
%
That is, a node should only receive a message once in the flooding operation.
%
Unfortunately, with most algorithms the same messages is received multiple times for each node.
%
These are unnecessary duplicated messages that are wasting network bandwidth and energy. 

\paragraph{\textbf{Coverage}}
is the percentage of nodes in the network that receive a message.


\paragraph{\textbf{Broadcast time}} is the time required for a flood operation to reach full coverage.
%
Notice that it is only measured when all the participants receive the message. We do so because it is the only way of comparing two protocols with different coverage.
%
In other words, this metric cannot be analyzed in isolation; instead, we should look also at the \textit{coverage}. 

\paragraph{\textbf{Energy consumption}}
is the energy consumed for each node during the experiment.
