\section{Evaluation}
\label{sec:evaluation}


\subsection{Experimental Setup}
\label{sub:setup}


For our performance comparison, we use OMNET++4.6/INET3.3, a simulation framework specifically aimed at networking algorithms.
%
This tool provides models of many protocols of the network stack such as MAC, 802.11g wireless communication and energy consumption ~\cite{10.4108/ICST.SIMUTOOLS2009.5585}.
%
In addition, it contains models to describe and deal with the mobility aspect.
%
In the following, we describe the simulation environment and the parameters used. 

\subsubsection*{Communication Scenario}

Our experiments are inspired by the scenario discussed in Section~\ref{sec:scenarios}.
%
In this scenario, attendees have a mobile device with IEEE 802.11 capability.
%
Many participants might attempt to broadcast messages at nearly the same time using a MANET.
%
Taking this into consideration, in our performance comparison  we set the number of broadcast messages to 300 and the interval among messages to the values $0.01$ and $0.5$ seconds, which are less than the speed of moving nodes.
%
These two values allow us to evaluate the protocols under heavy and light network load.
%
Since some algorithms build a topology to drive the flooding operation, there is a warm-up period before the first message is broadcasted that protocols can use to create any initial structure.
%
Finally, in our evaluation we stop each experiment a fixed amount of time after the beginning of the last flooding operation.

\subsubsection*{Density}

We use three parameters to characterize the density of the network: the transmission range, the map size and the number of nodes.
%
As shown in~\cite{Penrose2003}, there is dependency relationship between these parameters that is captured by the theory of random geometric graphs and allows us to build network topologies with a given density.
%
In our experiments, all nodes have a transmission range of 20m. \footnote{
	Theoretically, IEEE 802.11 devices allow communication in a range between 20 and 140 meters depending on the line of sight.
	Previous empirical tests show that it can effectively be between 20 and 30 m in indoor or crowded places~\cite{Garbinato2010}.}
while the number of nodes in the network is 200.~\footnote{comment on this number}
%
To vary the node density, we simply vary the map size but keep it as squared map.
%
Table~\ref{tbl:densisty-parameters} summarizes the simulations parameters we use to configure the density.

\subsubsection*{Mobility}

In our evaluation, we use the \textit{truncated-levy walk} (LW) mobility model, as it characterizes the mobility traces of humans carrying wireless devices~\cite{Rhee:2011}.
%
This model generates traces composed of frequent short walks and occasional long rides to distant locations.
%
In our context, we define two scenarios: with mobility at walking speed and without mobility.
%
We set the parameter of our LW model in such a way that the average walking speed is close to $1.4m/s$, a value reported in the literature~\cite{Browning390} as an estimation of the preferred walking speed.
%
To do so, we use the following values:

\begin{table}[ht]
	\footnotesize
	\centering
	
	\begin{tabular}{lcp{3.5cm}}
		\textbf{Parameter} & \textbf{Value} & \textbf{Description} \\
		
		\midrule
		FL\_EXP & -3.9 & Exponent of the flight length distribution \\
		FL\_MAX & 50 & Maximum value of the flight length distribution \\
		WT\_EXP & -1.8 & Exponent of the waiting time distribution \\
		WT\_MAX & 100 & Maximum value of the waiting time distribution \\
	\end{tabular}
	
	\caption{Configuration of the LW mobility model.}
	\label{tbl:mobility-parameters}
\end{table}

Afterwards, we check the traces to guarantee that the average speeds are indeed close to $1.4m/s$, and the topology remains connected all the time.

\subsubsection*{Algorithm specific parameters}

The behavior of each protocol depends on the values of its parameters.
%
To configure these parameters in a meaningful way, we choose values previously reported in the literature.
%
For instance, we use 0.5 seconds as the \textit{hello time} for both \textit{MPR} and \textit{node-degree-based} CDS.
%
In the case of \textit{ABBA}, we use 0.5 seconds as the maximum waiting time.
%
Finally, for \textit{ProbFlood} we assign the values $k=15$, $\sigma=1$, and $\textit{hello time} = 0.5$.


\subsection{Performance comparison results}

In this Section we present performance results in terms of following five metrics:


\textit{Saved rebroadcasts} --
number of messages that the nodes do not send thanks to the use of a particular broadcast algorithm.
%
More formally, let $k$ be the number of observed retransmissions during the flooding of a message using algorithm $a$; and $n$ the number of nodes in the network; then, we save $n - k$ rebroadcast by using $a$ instead of \textit{simple flooding}.
%
This metric is useful to measure the efficiency in terms of both network and energy usage. 

\textit{Duplicated messages} --
number of extra times a message is received.
%
That is, in a perfect situation a node only need to receive a message once.
%
But with most algorithms the same messages is usually received multiple times.

\textit{Coverage} --
percentage of nodes in the network that receive a message.


\textit{Broadcast time} -- time required for a flood operation to reach full coverage.
%
It is only measured when all the participants receive the message because this is the only way of comparing protocols with different coverage. 

\textit{Energy consumption} --
energy consumed for each node during the experiment.

 
For each broadcasting approach,  we present the results for several scenarios as we discuss in Section~\ref{sub:setup}.
%
To do so, we present the results for each metric with and without mobility.
%

\subsubsection{Energy Consumption}

The following section analyses the energy consumption of the studied approaches.
%
The energy consumption of a node depends on several factors: the \textit{number of message sent}, the \textit{number of messages received}, and the \textit{network saturation in the vicinity} of the node.
%
The \textit{number of message sent and received} are important because, every time the node sends or receives a message, the \textit{transmitter} or \textit{receiver} components of the radio change to a more power hungry mode.
%
Hence, the broadcast messages retransmitted as well as the control messages have a direct influence on energy consumption.
%
The \textit{network saturation in the vicinity} of the node is also important due to the way the MAC layer is implemented.
%
In CSMA, a node must receive an \textit{ACK} notification when a message is received, otherwise the message is resent.
%
The goal of this strategy is to increase the reliability of the network, but it has a strong negative effect in terms of energy consumption when the network is saturated.
%
Since in this case both messages and ACK notifications are often lost, the MAC layer keeps resending message and consuming energy in the process.
%

Figures~\ref{fig:a-energy} and~\ref{fig:b-energy} show the values of energy consumption for the static and mobility settings respectively.
%
Since each node sends and receives different number of messages, we use \textit{boxplots} to present the full distribution of power consumption.
%
Due to space limitations, we do not present the plots for all densities.
%
Instead, we are only showing plots for those densities were there is a significant change in the patterns of energy consumption.
% 

\begin{figure*}[htb]
	\centering
	\subfigure[Static Scenarios]{\label{fig:a-energy}\includegraphics[page=1, width=0.90\textwidth]{fig/results-static.pdf}}
	~
	\subfigure[Mobility Scenarios]{\label{fig:b-energy}\includegraphics[page=1, width=0.90\textwidth]{fig/results-mobility.pdf}}
	\caption{Energy consumption for different densities and mobility scenarios. Each box show the distribution of energy consumption for all the nodes in a scenario.}
	\label{fig:energy-consumption}
\end{figure*}


The first thing to note is that, as expected, \textit{simple flooding} consumes more energy in all scenarios.
%
Also interesting is that both CDS-based approaches, namely \textit{MPR} and \textit{node-degree}, always outperform other approaches when there is no mobility.
%
This is consistent with the results depicted in Figures~\ref{fig:a-saved} and~\ref{fig:a-duplicated}, which show that nodes send and receive fewer messages in these approaches.
%
In the case of \textit{ABBA} and \textit{ProbFlood}, our experiments do not show a single value of density where these algorithms behave better than \textit{MPR}.
%
This is interesting because it indicates that properly using control messages to build an underlying topology is worth in terms of power consumption when the interval among two broadcast messages is close to the interval among control messages.
%

As depicted in Figure~\ref{fig:b-energy}, the behavior of these protocols change in the mobility scenarios.
%
In such scenarios, \textit{ABBA} outperforms \textit{MPR} when the density is low or medium (5, 10, 15).
%
Only when the density is greater than 20, MPR becomes competitive once again.
%
In correlating these results with Figures~\ref{fig:b-saved} and ~\ref{fig:b-duplicated} we notice that the nodes send fewer messages with \textit{ABBA} than with \textit{MPR}.
%
We also notice that the number of duplicated messages received is closer than in the static scenarios.
%
%Although This changes when densities above 30 because the control 
%
In studying these results we notice that \textit{MPR} cannot maintain a completely up to date underlaying topology due to the mobility.
%
As a consequence, it fails in reducing the number of relays nodes and the power consumption is high.

These results are of interest because they show two parameters of a scenario that may impact the decision of what algorithm to use for broadcasting.
%
The first parameter is the mobility of nodes and the second is the ratio between the broadcast interval and control message interval.
