We then present two broadcast protocols, one based on controlled flooding, the other based on an overlay, that we will combine to allow emergent overlays.

\subsection{System and communication models}
\label{sec:background:model}

We consider an arbitrary number of nodes $n_{i},n_{j},\dots$
These nodes are mobile in a 2-dimensional space.
They communicate using wireless transceivers that can emit network frames using \emph{local broadcast}.
We consider the fixed-range model: Local broadcasts can be received by every node within a transmission range Tx.
Figure~\ref{fig:manet-comm-model} presents the coverage areas for nodes $n_{1}$ and $n_{2}$.
Node $n_{3}$ is in range of both and may receive frames from either $n_{1}$ or $n_{2}$ when active in listening mode (i.e., not sending itself).
Sending and receiving frames consumes energy from the node's limited power supply.
We do not consider the availability of geolocation information (GPS) on the devices.

The main obstacle to reliable broadcast in MANETs is the presence of \emph{collisions}.
A collision may happen when two nodes have overlapping coverage areas.
If nodes $n_{1}$ and $n_{2}$ send frames at the same time then it is impossible for $n_{3}$ to successfully receive either of the frames.
The same applies to a node that is currently sending and will not receive locally broadcast frames from other nodes in range.
Detecting collisions is not possible directly.
This phenomenon is known as the hidden terminal problem~\cite{hidden-terminal-problem}.

\subsection{MAC protocol}
\label{sec:background:mac}

To offer reliable local broadcast, a MAC (Medium Access Control) protocol must detect missed receptions due to collisions and implement frame retransmissions.
There is a tradeoff between the number and cost of such retransmissions, and their impact on collisions: Too many retransmissions may make things worse and create local broadcast storm~\cite{BroadcastStormProblem}.
Another difficulty is due to mobility: Nodes are not aware of the identities of other nodes within their coverage areas.

\subsection{Broadcast protocols}
\label{sec:background:broadcast}

The goal of broadcast is to reliably send a message to all nodes in the network, subject to mobility and collisions.
The source can be any node in the network.
Nodes may forward a message using local broadcast upon its first reception.
Subsequent receptions are \emph{duplicates} and do not lead to forwarding.
The target is to reduce the number of necessary relays while ensuring a high or total coverage, measured as the number of nodes that receive the message during the broadcast.
We note that incomplete broadcasts may be addressed through a palliative mechanism such as periodic anti-entropy~\cite{leme2017analyzing}, but the use of these techniques is orthogonal to our goal of reaching high coverage in the first place.
Broadcast protocols can be classified in two families depending on how they choose relay nodes~\cite{survey-ruiz}.
In controlled flooding, nodes decide whether to be a relay when receiving the message.
In overlay-based approach, the selection of relays is the result of an overlay creation process that requires specific control messages.
We present in the following the two protocols that we use in the rest of this paper.

\begin{enumerate}
	\item Start with an empty set of relay nodes.
	\item Mark every node $r \in N(x)$ as relay node, if a node $m \in N_{2}(x)$ exist such that nodes $m$ and $x$ are the only two one-hop neighbors of $r$.
	\item While there is a node $n \in N_{2}(x)$ that is not covered, chose another relay node $r \in N_(x)$ with the highest number of neighbors.
\end{enumerate}

\subsection{MAC layer and collision avoidance}
\label{sec:background:mac}
Wireless distributed MAC (Medium Access Control) protocols such as IEEE 802.11 coordination function allows nodes to share a common channel for data transmission and relies in a collision avoidance mechanism commonly known as \emph{virtual carrier sensing}~\cite{ieee1997wireless}.
%
This mechanism is a handshake protocol between a sender and any receiver that is positioned at the senders broadcast area.
%
When a node is willing to send a data packet, it starts by sending a Request To Send (RTS) packet.
%
On reception of RTS a receiver  holds the medium to expect data from RTS sender by answering with a Clear To Send (CTS) packet.
%
Once the sender receives CTS, the data transmission begins and it is tagged as successful transmission if the receiver acknowledge the sender (with another packet) when all data packets were correctly received.
%
In case interferences take place in any of the phases of the previous handshake protocol, nodes respond with error packets.
%
This is a drawback in collision avoidance mechanisms because nodes waste bandwidth by sending error packets along with data packets.


%
Virtual carrier sensing is prone to errors when hidden nodes to senders interfere with the handshake protocol, this phenomenon is known as the \emph{hidden terminal problem} and it is depicted in figure~\ref{fig:mac-example}.
%
Suppose node $n_{1}$ initiates the virtual carrier sensing protocol with node $n_{2}$, notice in the figure that node $n_{3}$ is hidden for $n_{1}$.
%
Once $n_{2}$ receives an RTS packet from $n_{1}$, the former replies with a CTS that will reach $n_{3}$.
%
Given that $n_{3}$ has not previously initiate an exchange with $n_{1}$, node $n_{3}$ sends an error packet and may interrupt the data transmission between $n_{1}$ and $n_{2}$.
%
Improved protocols to deal with the hidden terminal problem, such as the one presented in~\cite{mac-with-cd}, use out-of-band packets to explore the channel conditions without interfering with data transmission, this techniques achieve both collisions detection and avoidance.
%

%
One of our contributions is a virtual carrier sensing protocol that do not require the transmission of error packets and count the number of potential collisions of data packets (refer to section~\ref{sec:mechanisms}).
%
We aim to take advantage of the local broadcast approach to improve reliability of data packets and, at the same time, ameliorate the utilization of bandwidth.
%
We do not argue that our MAC protocol outperforms the implementation in the IEEE 802.11 coordination function, in fact, the evaluation of our MAC protocol is left as future work.

\subsection{Broadcast algorithms}
\label{sec:background:broadcast}
Broadcast is a fundamental operation for distributed applications in MANETs.
%
This operation consist in delivering a message from a source node to every other node in the network.
%
We provide a more formal definition of broadcast.
%
In a network of $N$ nodes a broadcast protocol aims to find a subset of \emph{relay nodes} with $R \subset N$, such that, if a source node $s \in R$ sends a message \emph{m} and only those nodes in the set $R - \{s\}$ forwards such message, \emph{m} will be received at least once by every node in $N$.
%
A vast amount of broadcast protocols have been proposed and aim to minimize the set of relay nodes without decreasing reachability.


%
The lack of a central authority in MANETs requires to focus on distributed broadcast protocols that relay only in local data available at each node, avoiding any contact to services out of the network (like GPS or monitoring services).
%
Ruiz and Bouvry have surveyed broadcast protocols approaches~\cite{survey-ruiz} and classify them in two groups: topology-based and non topology-based protocols.
%
Each group in this classification distinguishes protocols that vary the transmission range (Tx) of transceivers from those who use a fixed Tx.
%
In order to let each node cover a fixed broadcast area, and this area of coverage is the same for every node in the network, in this paper we only considers protocols that use a fixed Tx and no GPS coordinates are fetched from an external service.
%
We now give a general overview of the classification proposed in~\cite{survey-ruiz} and describe the broadcast protocols we use in our adaptive approach (described in~\ref{sec:mechanisms}).

%
\subsubsection{Topology-based broadcast protocols}
\label{sec:background:broadcast:overlay-based-protocols}
Protocols in this category build and maintain a distributed wireless topology which is formally known as a Connected Dominating Set (CDS).
%
Basically, a CDS is also a set of relay nodes (as explained in~\ref{sec:background:broadcast}).
%
A CDS have the property that every node out of such set is adjacent to at least one relay node~\cite{cds-explained}.
%
This property enforce broadcast because nodes out of a CDS receive messages from at least one of their adjacent relay nodes and naturally, every relay node forwards a message at least once.
%
Nodes build and maintain a CDS via the exchange of networks packets commonly known as \emph{control messages}.
%
These messages contain data of nodes surroundings.
%
Topology-based broadcast protocols use control messages to decide whether or not nodes are relay nodes.
%
This decision is computed on every node and is prior to forward incoming data packets.
%
In general, the objective of a topology-based protocol is to figure out relay nodes and label them.

%
In ~\cite{mpr}, Qayyum et al. propose a topology-based broadcast protocol called Multi-point Relaying (MPR).
%
The MPR protocol assumes that every node knows two sets, its one-hop and two-hop sets of neighbors.

%

	\item Mark every node $r \in N(x)$ as relay node, if a node $m \in N_{2}(x)$ exist such that nodes $m$ and $x$ are the only two one-hop neighbors of $r$.
	\item While there is a node $n \in N_{2}(x)$ that is not covered, chose another relay node $r \in N_(x)$ with the highest number of neighbors.
\end{enumerate}

\subsubsection{Broadcast protocols not using topologies}
\label{sec:background:broadcast:non-overlay-based-protocols}
Protocols of this category decides whether or not nodes act as relays on the reception of messages.
%
Nodes follows a more reactive approach than the one performed in topology-based protocols because no prior computation is required.
%
An example is the straightforward approach \emph{simple flooding}, where nodes forward only once messages that haven not been previously heard.
%
This approach has been proven to be effective in networks with high mobility~\cite{ObraczkaK_2001}, on the other hand, the network is overwhelm with redundant messages that rapidly increase the likelihood of collisions.
%

%
Ni et al. propose in~\cite{BroadcastStormProblem} several techniques that perform controlled flooding approaches based on the number of received messages, the intersection of several broadcast areas or using probabilistic schemes.
%
For instance, the counter-based approach works as follows.
%
Every node use a predefined threshold for allowed receptions.
%
When a message $m$ is heard for the first time a counter $c$ of allowed receptions for such message is set to one.
%
Then, a timer $t$ is set to a random duration that serves to wait for additional receptions of $m$.
%
In case another copy of $m$ is heard, the timer $t$ pauses, the counter of receptions for such message increases of one and finally, the timer resumes.
%
When $t$ has expired and the counter of receptions for $m$ is lower than the threshold of allowed receptions, then $m$ is forwarded; otherwise, the message is not forwarded.
%
In our adaptive approach we use the previous counter-based approach to broadcast in sparsely dense regions of the network where nodes move faster.

\subsection{Autonomous adaptation}
\label{sec:adaptation-background}
Adaptation refers to the ability of a system to change its behavior based on the observations of the underlaying environment.
%
Examples of such observables in mobile nodes are: number of nodes within broadcast areas (density), interference in signal transmissions, rate of collisions or used bandwidth.
%
Local information of nodes is an observable as well, such as remining battery level or nodes relatively velocity (in case a giroscope or accelerometer is available).
%
These observables may not be homogeneous in all nodes.
%
Some nodes may be positioned in densely-populated areas while others may be in sparsely-populated areas, this situation occurs in the music festival use case (as described in section~\ref{sec:introduction}).

%
We believe that there is no one-fit-all solution to broadcast in MANETs, this has been shown by priors works on adaptive schemes~\cite{hypergossiping,2001:AAR:876878.879323,adaptive_group_com_iscc02}, where a switching criterion or ~\emph{adaptation policy} is triggered to perform broadcast protocol of the same class.
%
Given that the operating conditions in a network are heterogeneous, adaptation policies may concern only a set of nodes.
%
The application of adaptive policies are based on the system observables and generally, they are applied collectively by nodes.
