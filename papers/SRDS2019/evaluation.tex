\textbf{metrics}
we should have a table listing these.
All metrics should be recorded together with the class (sparse or dense) of the node.
\begin{itemize}
	\item coverage \er{these are actually two metrics: (1) average percentage of nodes covered by a dissemination and (2) percentage of the disseminations that reached all nodes.}
	\item sent/received messages at the application level (number of calls to the MAC layer)
	\item sent/received data frames (number of sendings/retransmissions at the MAC protocol level)
	\item derived from the two previous, average number of MAC retransmissions of the payload (number of MAC retransmissions / number of calls)
	\item data frame error rate: number of not heard ACKs at mac layer over all data frames; this is our way of measure collisions
	\item rebroadcast: comparison of number of sendings of application-level messages with real pure flooding (also subject to the same collisions and conditions etc. -- this is not the idealized ground truth)
	\item number of duplicate receptions
\end{itemize}

\textbf{Experiments}
\begin{enumerate}
	\item setup: Expected figure: a 2-D representation of the nodes at time t0, with a dashed square showing the POI/dense zone in the middle.
	Nodes should all have the same color (white). We will reverse the use of color to show the protocol being used. 
	For two or three nodes, show a circle using a transparent pale color (as for the figures in the beginning of the paper) that show their transmission range. The figure \emph{must} be in vectorial (PDF or eps) format.
	\item baseline benchmark
	\begin{itemize}
		\item we consider the controlled flooding (one instance) and the MPR (3 instances, for the three frequencies).
		\item performance of using a single protocol. What you want to show is that an overlay everywhere leads to bad coverage, and flooding everywhere leads to high costs. The coverage should be measured and mentioned in a table, together with the number of collisions.
		See placeholder for details of the table.
		\item the plot will be a two-column-wide plot with three embedded subplots:
		\begin{itemize}
			\item Plot 1: coverage \#1 and coverage \#2. 
			Y axis is \%-age from 0 to 100. 
			X axis is 12 slots: 3 for the controlled flooding (CF), 3 for each of the configurations of MPR. 
			Each triplet is (a) full network (b) only nodes in central area (c) only nodes in external areas.
			For each in the triplet, use one bar showing the percentage.
			\item Plot 2: \# of messages at the application level.
			Y axis is 0 to max \# of messages
			X axis is exactly as previous.
			For each tic in a triplet, plot one violin plot showing the distribution of the number of messages over all nodes.
			The number of messages includes control messages.
			Since this number is known and the same for all nodes, show it as a small vertical bar (dashed) for the three MPR configurations. The meaning of the bar will be shown in the legend of the plot.
			\item Plot 3: \# of messages at the MAC level.
			Y axis is 0 to max \# of messages
			X axis is exactly as previous.
			For each tic in a triplet, plot the same as previous but for the number of MAC retransmissions. No need for the small bar of the previous plot in MPR configurations.
		\end{itemize}
	\end{itemize}
	\item evaluation of the observables
	\begin{itemize}
		\item goal is to know how far the observables are far from the truth as known by the simulator
		\item a first plot for density: distribution of the difference between the ground truth and the measured one, for the different ways to measure density
		\item Single plot: Y axis is difference (negative or positive) from ground truth.
		X axis is one triplet of tics per mechanism available to measure density (same meaning for the triplet as before)
		For each tic, violin plot of the distribution of differences from ground truth.
	\end{itemize}
	\item evaluation of the policies
	\begin{itemize}
		\item goal is to evaluate how good are the policies in deciding, and what is the impact on performance. Two main metrics are: quality of the resulting graph, and costs of the resulting hybrid system. Should include graphical representation of the selections.
	\end{itemize}
	\item comparison with related work
	\begin{itemize}
		\item running the two other approaches and comparing them to the emergent overlays (only with the best configuration found in the previous)
		\item should ideally happen on a more sophisticated setup with multiple POIs.
	\end{itemize}
\end{enumerate}

\er{
Goal for this section: show experimentally that the proposed algorithms and protocols answer the research questions set forth in the introduction.
We aim at answering the following research questions:
\begin{itemize}
	\item Does the use of a single protocol in an heterogeneously distributed MANET lead to sub-optimal performance?
	\item Is it beneficial to use different protocols for broadcast in a heterogeneously-distributed MANET, and does it reduce contention/collisions, costs, and improves overall reliability?
	\item What is the relative impact of heterogeneity in motion, and heterogeneity in placement, to the difference in performance and reliability observed in the complete MANET?
	\item What is the cost of the interoperability mechanism when a subset of the network decides to adapt and emerge an overlay in its region?
	\item Are the observables available locally to each node a good representation of the actual deployment environment of each node?
	\item How effective are the adaptation strategies in autonomously deciding on the emergence of overlays or the use of flooding-based broadcast?
\end{itemize}

	\item Experimental setup: simulator, traces, models for the nodes energy consumption, etc.
	\item Recap that we use our MAC layer
	\item Microbenchmarks with the square setup
	\item Macrobenchmarks with more complex setups, with different dense/dynamic regions over space
\end{itemize}
