\section{Experimental Scenario}
\label{sec:scenarios}

%
\changed{
Our experiments are inspired by a real life scenario: a \emph{manifestation}, where individuals use their phones to communicate with others and the efficient dissemination of messages to participants is critical.
}
\deleted{
Our experiments are inspired by a real life scenario: a physical \emph{demonstration} where the infrastructure for mobile communication is not able to serve the amount of clients and where individuals use their mobile phones in an ad-hoc mode to communicate.
}
%
Our evaluation of broadcast algorithms for MANETs is driven by two variables: \emph{network density} and \emph{nodes mobility}.
%
\deleted{
We consider two parameters that influence the performance of broadcast in MANETs: \emph{network density} and \emph{nodes mobility}.
}
%
In the following, we describe\deleted{ the simulation environment and} the parameters used in our study.

%\subsection*{Simulation tool}
\noindent
\textbf{Simulation tool.}
We rely on OMNET++4.6/INET3.3, a simulation framework to evaluate networking algorithms~\cite{Varga:2008:OOS:1416222.1416290}.
%
This tool provides a full implementation of the standard IEEE 802.11g.
%
In addition, it contains models to cope with mobility and energy consumption.

\noindent
\textbf{Communication Scenario.}
%\subsection*{Communication Scenario}
In our experimental scenario, all attendees have mobile phones to communicate through WiFi.
%
Participants use such devices to broadcast and they might attempt to do so at nearly the same time.
%
\deleted{
The payload of messages is usually \emph{small} because most of them are generated using the input capabilities of mobile devices.
}
%
To simulate these conditions, we set our experiments to perform \nrMessages{} broadcast messages and the frequency between them is $0.5$s.
%
In addition, the source of each message is randomly selected during the generation of the network (see next subsection).
%
Finally, the content of each message is randomly generated, unique and with a length of 32 bytes. 
%
%These two values allow us to evaluate the protocols under heavy and light network load.
%

\noindent
\textbf{Nodes Density.}
%\subsection*{Nodes Density}
We are interested in generating scenarios with different nodes densities to simulate more accurately our use case.
%
%In particular, the density in the vicinity of each node must equal a given value plus/minus a threshold.
%
We use three parameters: transmission range (Tx), map size and number of nodes.
%
As shown in~\cite{Penrose2003}, there is a dependency between these parameters that  allows us to build networks with a given density, by using random geometric graphs.
%
In our experiments, all nodes have a Tx of 20~m.~\footnote{Theoretically, IEEE 802.11 allows communication in a range between 20 and 140 meters, depending on the line of sight.
Previous empirical tests show that it can be between 20 and 30 m in indoor or crowded places~\cite{Garbinato2010}.} The number of nodes $N$ is fixed to \nodesNumber{}, which is the mean value reported by previous studies on the size of manifestations in Western Europe~\cite{kriesi1995new}.
%
To create a network with a given density, we use Tx and $N$ to compute the map size \deleted{using the aforementioned dependency relationship}.
%
Then, we generate a laying on the map by using random geometric graphs.
%
The output of this procedure is a network with the desired density.
%
\deleted{Table~\ref{tbl:densisty-parameters} summarizes the simulations parameters we use to configure the density.}
%
We instantiate \densitiesNumber{} networks of \nodesNumber{} nodes each and set the densities to  {5,10, \dots, 40} nodes, a range of values that is frequently found in the literature.
%
This leads to a map size of $354 \times 354$m while the smallest map is $125 \times 125$m.


\noindent
\textbf{Mobility.}
%\subsection*{Mobility}
In our evaluation, we use the \emph{truncated-levy walk} (LW) mobility model, as it characterizes the mobility traces of humans carrying wireless devices~\cite{Rhee:2011}.
%
This model generates traces composed of frequent short walks and occasional rides to distant locations.
%
We define two kind of scenarios: one without mobility (\emph{static}) and another with mobility (\emph{dynamic}) at a walking speed of $1.4$ $m/s$ -- an estimation of the preferred walking speed~\cite{Browning390}.
%
The generation of \emph{static} scenarios was presented in the previous subsection.
%
To generate \emph{dynamic} scenarios, we begin with a \emph{static one}.
%
Then, we use the LW model to generate mobility traces for each node.
%
\deleted{
The parameters of the LW model are set in such a way that the average node speed is close to .
}
%
\deleted{To do so, we use the following values to feed the mobility model:}

Afterwards, we perform several checks on the traces to guarantee that: i) the average speeds are indeed close to $1.4$ $m/s$, ii) the node density is the desired one during all the simulation time, and iii) the topology remains connected all the time.~\footnote{Except for a very low density (5) where we are unable to generate a topology that remained connected during all the experiments.}
%
Should any of these checks fail, we discard the mobility traces.
}

\noindent
\textbf{Energy Settings.}
%\subsection*{Energy Consumption}
\deleted{
The power consumption must be considered in evaluating protocols that use wireless communication.
}
%
Given that this metric depends on the Wi-Fi chip, we model power consumption using the specifications of a commercial chip found in modern mobile devices.
%
The chip Broadcom BCM4329~\cite{BCM4329}, which supports Wi-Fi 802.11g on the 2.4 GHz frequency band.
%
Its energy consumption per operation modes is as follows: sleep (648 nW), listen (244.8 mW), receive (295.2 mW), transmit (1206 mW).
%
These values are set in the consumption model of INET.

\deleted{

To simulate this chip, we use the \emph{StateBasedEnergyConsumer} model provided by INET.
%
This model measures how many Joules were consumed based on the time the chip spends on each mode (as described in Table~\ref{tbl:wifi-chip}).
}
%
\deleted{Formally, this energy consumption model uses three functions: $c : M \mapsto \mathbb{R} $, $r_m: \mathbb{R} \mapsto M$ and $t_m: \mathbb{R} \mapsto M$ where $M$ is the set of operation modes of the chip, $c$ is the consumption of the chip on each mode, and functions $r_m, t_m$ map from simulation time to operation modes of the \emph{receiver} and \emph{transceiver}, respectively.
%
INET then computes the energy consumption $C(t)$ using:  $C(t)=\int_{0}^{t_\textit{simulation}} (r_m \circ c) (t) + (t_m \circ c) (t) \textit{dt}$.
%
The function $m$ is given and INET computes both $r_m$ and $t_m$ during the simulation.}


\noindent
\textbf{Algorithm-specific parameters.}
%\subsection*{Algorithm-specific parameters}
The behavior of each protocol depends on the values of its parameters.
%
To configure these parameters meaningfully, we choose values previously reported in the literature.
%
For instance, we use 0.5s as the \emph{hello time} for \emph{MPR},  \emph{ProbFlood} and \emph{CDS-based}.
%
In the case of \emph{ABBA}, we use 0.3s as the maximum waiting time.
%
Finally, for \emph{ProbFlood} we assign the values $k=15$ and $\sigma=1$.

%\noindent
%\textbf{Simulation time.}
\subsection*{Simulation time}
As mentioned in Section~\ref{sec:background}, some algorithms build a topology to drive the broadcast operation.
%
To guarantee that the first broadcast message is properly handled by all protocols, we set an initial warm-up period of 5s\deleted{before the first message is broadcast}.
%
This phase is used to create the initial topology in CDS-based algorithms.
%
%This time is used by  protocols can use to create any initial structure.
\deleted{
Likewise, \deleted{in our evaluation,} we stop each experiment a fixed amount of time (5s) after the beginning of the last broadcast operation.
%
This grace period allows the last message to reach all nodes.
}
%
The total simulation time is then $10 + {\delta t} \times M$, where ${\delta t}$ is the interval between broadcast messages and $M$ is the number of scheduled messages.
