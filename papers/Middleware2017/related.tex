Regarding adaptive-based broadcast algorithms, Hypergossiping~\cite{hypergossiping} is a broadcast strategy protocol designed for MANETs where the authors combine two different protocols: Probabilistic Flooding~\cite{Ni1999} (known as gossiping in the paper) and HyperFlooding~\cite{Cheng2005}. 
Hypergossiping was designed for partitioned networks where partitions of mobile nodes are constantly changing.
Inside each partition, nodes use the Probabilistic Flooding protocol to send and receive messages adapting their local probability based on the local density of the node.
This density is obtained by periodically sending HELLO messages.
In addition, if a new node is detected in the partition, this node may receive packets using this protocol from partition nodes.
%The Probabilistic Flooding protocol is used for in-partition forwarding and rebroadcasts some of the packets in case the node detects a joint with another partition.
Thus, nodes can detect partitions by simply comparing recently received sets of packets.
In case these sets differ, the node will re-broadcast the packet using HyperFlooding.
Therefore, Hypergossiping is an adaptive algorithm for one protocol that is using two protocols and HELLO messages to adapt each partition depending on the density of the nodes inside this partition.
Given that nodes are using the same protocol to communicate among them, there is not a protocol switch mechanism among the partitions and Hypergossiping cannot work with partitions using different protocols.
On the other hand, our solution can work with different protocols without modifying them.
In addition, there is no need for sending periodic HELLO and piggybacked messages either, reducing message collision and, consequently, energy consumption.

Zhang et al.~\cite{Zhang2005} propose an approach called Dynamic Probabilistic Route (DPR) discovery, based on a combination of probabilistic and counter-based schemes.
Each node contains a probabilistic P variable depending on its local density.
Not periodically control messages are used to determine the neighbours, however, every node in the network piggybacks the set of its local neighbours nodes to the broadcast message.
This information is used for the receiver nodes to determine their own local density. 
In order to estimate its neighbour list, each node waits a threshold time since the first broadcast message is received. If another broadcast message is received in that period of time, the sender node will be added to the neighbour list.
Depending on the density of the node, it will be set as sparse or dense networks. In case of the node is in a sparse network, it will always retransmit the message.
However, if the node is in a dense network, the probability P to retransmit a broadcast message will be based on the density of their local neighbours as well as a cumulative amount of neighbour mobile nodes.
Additionally, in case of a node receives a message containing the same list of neighbours as its local list, then the node will not broadcast the message.
As a result, the necessity of the nodes to know in advance their number of neighbours to calculate the probability P, adds a waiting time to estimate their local neighbours list, what produces an extra overhead.


Viswanath and Obraczka~\cite{Viswanath02anadaptive} present two variants of an adaptive broadcast algorithm for MANETs that allows each node to switch among 3 different flooding modes: \emph{plain}, \emph{hyper}, and \emph{scoped} flooding. 
Hyper flooding is used to obtained the high reliability necessary for mobile scenarios with high mobility. It also has the highest overhead. 
In contrast, scoped flooding is used when nodes have a lower velocity, aiming to reduce redundant broadcast messages and obtaining a lower overhead. 
The nodes periodically exchange HELLO messages to keep track of their one-hop neighbours, adding to each HELLO message node speed and direction information. 
Each node has two thresholds (\texttt{low\_threshold} and \texttt{high\_threshold}) and it can modify these thresholds depending on the information received by the HELLO messages and their past history. 
If the current velocity of the node is higher than \texttt{high\_threshold}, the node switches to hyper flooding. 
Conversely, if node velocity is lower than \texttt{high\_threshold} but higher than \texttt{low\_threshold}, the node switches to plain flooding. 
Otherwise, the node switches to scoped flooding. 
Additionally, the authors present a second switching mechanism based on network load, which uses MAC-layer collisions as an indicator of network traffic.
In this switching method, each node computes the total number of collisions occurred in a specified time window.
%Therefore, each node can adapt both thresholds (\texttt{low\_threshold} and \texttt{high\_threshold}).
If the number of collisions is lower than \texttt{low\_threshold}, the node switches to hyper flooding mode. If the number of collisions is greater than \texttt{high\_threshold}, scoped flooding is selected.
Otherwise, plain flooding is selected.
This adaptive broadcast algorithm is based on the mobility or the collisions amount.
However, our proposal can adapt different kinds of broadcast algorithms, using the most suitable algorithm, such as counter-based or area-based among others, being more flexible for the requirements of diverse kind of situations.

Abdou et al.~\cite{Abdou2012} propose an adaptive broadcasting protocol for MANETs called Smart-Flooding. 
This mechanism utilises the Shadowing Pattern~\cite{Dhoutaut2006}, a propagation model that is a realistic and probabilistic scheme based on outside monitored communications, together with an evolutionary algorithm created by the authors. 
According to this Shadowing Pattern, each node modifies its own local parameters using the evolutionary algorithm and the network density calculated by periodically sending HELLO messages.

Cartigny and Simplot~\cite{ProbFlood} propose probabilistic algorithms for MANETs combining a simple probabilistic algorithm, a distance protocol, and a neighbour elimination scheme~\cite{Peng2000,Stojmenovic20028} to reduce the number of broadcast messages sent through the network. 
Each node sends periodic HELLO messages in order to be aware of its environment. 
These algorithms are adaptable to the network topology, however, they do not achieve full coverage for broadcast messages.

Xu and Gerla~\cite{Kaixin2002} describe a heterogeneous routing protocol based on a clustering scheme that allows different MANET broadcasting protocols to work together. 
The authors predefine specific nodes to be backbone nodes. These can communicate among themselves using long distance communications as compared to non-backbone nodes. 
Each backbone node creates a cluster with a specific protocol used by the nodes contained in its area. 
Therefore, when a broadcast message is sent, the backbone nodes send the broadcast message among them, and after that, among nodes in their respective cluster areas.

Compared to our research, our approach achieves full broadcast coverage permitting the network being used by different broadcast algorithms and also defines a switching mechanism that allows nodes of different broadcasting algorithms to communicate among themselves. 
Additionally, the work presented in this paper does not required to add HELLO or piggybacked messaging schemes to protocols.
