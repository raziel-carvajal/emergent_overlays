\section{Interoperability in \acl{bps}}
We assume that a set $\mathbb{P}$ of broadcast protocols is in execution in a deployed mobile network of $\mathbb{N}$ nodes where each node $n_{i} \in \mathbb{N}$ runs only one protocol $p_{j} \in \mathbb{P}$ at a time.
%
Our aim is letting a node $n_{i}$ chose in an autonomous way a certain protocol $p_{j}$, this decision is based on the local information available at the node.
%
Such information may be, and it is not limited to, remaining battery, signal strength of received packets or the node relative speed.
%
But we omit the case where $n_{i}$ is running more than one protocol concurrently.

%%
When $\mathbb{P}$ contains only one protocol the reachability of messages depends on the performance of such approach.
%
Notice that in our hybrid approach we do not intent to alter the internals of any protocol in $\mathbb{P}$.
%
On the contrarily, when the cardinality of $\mathbb{P}$ is $|\mathbb{P}| > 1$ packets may be lost.

%
Figure~\ref{packets-lost-ex} depicts a situation where a set of nodes $\mathbb{T}=\{t_{i} \mid i \in \{1, \ldots, 6\}\}$ run a topology-based protocol while nodes in $\mathbb{F}=\{f_{j} \mid i \in \{1, \ldots, 3\}\}$ run blind flooding.
%
Broadcast sessions initiated at $t_{1}$ form a tree such that a forwarding set composed of $t_{1}, t_{2}, t_{3}$ guarantees the message reception of every node at $\mathbb{T}$.
%
Even if nodes $t_{4}, t_{5}, t_{6}$ are within the communication range of some nodes in $\mathbb{F}$, their role as pure receivers in the tree avoids any node in $\mathbb{F}$ hearing from messages.

\subsection{Detection of border nodes}
%%%% INTEROPERABILITY ALGORITHM %%%%
\input{interop_algo}

Algorithm~\ref{interop-alg} is a simple mechanism we propose to deal with interoperability issues between nodes running different protocols.
%
We intent to increase the set of forwarding nodes from only one running protocol with a set we called \textit{border nodes}.
%
Intuition says that the bigger the size of this set the higher the reachability of nodes among broadcast sessions.
%
Border nodes are within the transmission range of other nodes running a different protocol.
%
In figure~\ref{packets-lost-ex} nodes $t_{4}, t_{5}, t_{6}$ are candidates of border nodes.
%
We consider that messages are vectors $(\iota, \tau, \rho, \varrho)$ with four entries where: $\iota$ is a unique identifier, $\tau$ defines either a control or broadcast message, $\rho$ refers to the running protocol at the sender and $\varrho$ is the message payload.
%
Control messages are beacons required by some protocols to operate and broadcast messages contain the information to disseminate.

%%
Our interoperability mechanism works as follows.
%
When nodes receive a message $msg$ that corresponds to the running protocol of the sender or this receiver was previously labeled as border node (line 10), $msg$ is broadcast; notice that the function \textit{broadcast} (line~\ref{interop-alg:bro}) hides the implementation of a \acl{bp}.
%
In case the running protocols between sender and receiver differs we distinguish between two cases (line 13):

\begin{itemize}

\item \textbf{Control message reception.}
%
This case initiates the election of border nodes.
%
We keep track of senders from a foreign algorithm with the set \textit{known\_nodes} (line 8), potential candidates of border nodes are within this set.
%
If receivers previously hear a beacon from a sender running a known foreign protocol, $msg$ is ignored.
%
Otherwise, we keep a reference of the knew known protocol (line~\ref{interop-alg:save-alg}) and a timer initiates (line~\ref{interop-alg:new-timer}).
%
When the timer expires (line~\ref{interop-alg:timer-expires}), we create a new border message \emph{b} (line~\ref{interop-alg:new-border-msg}) with the following fields:

\begin{itemize}

\item \textit{border node} (line~\ref{interop-alg:new-border-msg:chosen}): for the moment this is a random choice, alternatively we can piggyback senders remaining battery to control messages for selecting a border node with the higher value of energy
\item \textit{traveled hops} (line~\ref{interop-alg:new-border-msg:hops}): number of times $b$ will be forwarded
\item \textit{sender identifier} (line~\ref{interop-alg:new-border-msg:sender})
\item \textit{sender running protocol} (line~\ref{interop-alg:new-border-msg:sender-alg})
\item \textit{foreign protocol} (line 26): nodes running this protocol foster the border election procedure 

\end{itemize}
%
We now explore the case when nodes receive border messages (line 28).

\item \textbf{Border message reception.} Receivers decrease by one the number of traveled hops (line:~\ref{interop-alg:border-msg-case:dec}).
%
In case this counter has remaining hops, \textit{msg} is forward (lines: 30,~\ref{interop-alg:border-msg-case:fwd}).
%
Notice that the function \textit{forward} simply performs a retransmission within the communication range of the receiver.
%
Given that all packets have in a unique identifier further copies of previously known packets are ignored.
%
Furthermore, only one out of two possible situations take place.

%%
Either the receiver is a potential candidate of border node (line: 32) or it belongs to those nodes who foster the selection procedure (line 36).
%
The latter situation serves to cancel ongoing timers that triggered the border selection procedure by other senders (line:~\ref{interop-alg:border-msg-case:rm-timers}), that is, nodes running a foreign algorithm.
%
When the former situation occurs, the receiver is labeled as border node only if its identifier corresponds to the one in the message (line~\ref{interop-alg:border-msg-case:select-as-border}).


\end{itemize}


\subsection{Evaluation scenario}
\label{interop:scenario}

We simulate a situation where a crowd of humans carry mobile devices with WiFi capabilities (mobile phones, tablets, etc).
%
As shown in Figure~\ref{packets-lost-ex}, the area of communication has two regions, dense and sparse.
%
Each region contain 400 nodes and approximately the same surface where the dimensions of the whole area are 120 meters of height and width.
%
The aim of having such an arrangement is measuring the impact of increasing the forwarding set of one protocol with border nodes found with Algorithm~\ref{interop-alg}.
%
Nodes are spread uniformly in both regions and their initial position is chosen in a random way.
%
The number of nodes neighbors within the sparse region varies between 1 to 10 while those nodes in the dense region may have up to 40 neighbors.


\smallskip
\noindent
\textbf{Mobility.}
%\subsection*{Mobility}
We use the \emph{truncated-levy walk} (LW) technique to model mobility patterns of humans~\cite{Rhee:2011}.
%
The evaluation of Algorithm~\ref{interop-alg} take place in a static scenario where nodes do not move and in a dynamic scenario with mobility.
%
In this dynamic scenario, nodes move at a speed of 0.5 m/s within the dense region and the speed of those at the sparse region is 2.0 m/s. These rates of velocity are based on an estimation of the preferred walking speed of humans~\cite{Browning390}.
%
The LW model generates traces of frequent short walks and occasional rides to distant locations.
%
Nodes move within their region of density in the communication area without getting out of their designated region.


\smallskip
\noindent
\textbf{Broadcast protocols.}
In the static scenario, running protocols on each node are chosen in advance and nodes keep using this protocol until the simulation concludes.
%
Nodes in the sparse area use controlled flooding.
%
When a node receives a broadcast message for the first time, it starts a timer with a duration chosen randomly between the interval $[0,\dots,max]$. In our experiments the threshold \emph{max} is set to 10 ms.
%
When the number of received copies per message reaches a maximum number of receptions before the timer expires, the message is not forwarded. Otherwise, the retransmission take place.
%
This approach was first propose in~\cite{Ni:1999:BSP:313451.313525} to deal with broadcast storms.
%%
Nodes in the dense area use an approximation of a connected-dominating~\cite{qayyum:inria-00072756}.


\smallskip
\noindent
\textbf{Broadcast sessions.}
A total of 200 broadcast sessions are performed with a frequency of one second.
%
The source of each sessions is chosen randomly among all nodes.
%
The length of each message is 32 bytes. 


\smallskip
\noindent
\textbf{Simulator.}
We deploy our simulation with OMNET++4.6~\cite{Varga:2008:OOS:1416222.1416290} and the plug-in INET3.3 to model \acl{nets}.
%
This framework provides a full implementation of the IEEE 802.11g standard, we use the standard energy consumption model of this simulator.
%


\smallskip
\noindent
\textbf{Transceiver settings.}
Nodes have a transmission range of 10 m.
%
We model message transmission using the specifications of a commercial chip found in modern mobile devices, that is the chip Broadcom BCM4329~\cite{BCM4329}, which supports Wi-Fi 802.11g on the 2.4 GHz frequency band.
%
Its energy consumption per operation modes is as follows: sleep (1mW), receive (10mW) and transmit (100mW).

\subsection{Preliminary Results}
We deploy the static scenario described in section~\ref{interop:scenario} to measure: energy consumption, throughput of broadcast messages and reachability.
%
We perform 4 independent executions: simple flooding, the overlay-based approach MPR (multi-point relaying technique~\cite{qayyum:inria-00072756}) and two hybrid configurations. MPR runs in the dense area of both hybrid configurations whereas simple flooding and controlled flooding run in the sparse region of each configuration, respectively.

\smallskip
\noindent
\textbf{Energy consumption.}
MPR reduces the required energy to disseminate 200 broadcast sessions in an static wireless topology.
%
We observe that the forwarding set built per session contains up to 30\% of the nodes in the network while approximately 70\% of nodes act as receivers.
%
On the other hand, in a simple flooding where every node retransmits at least one leads in the lowest bound of performance for this metric.
%
The average consumed energy in our two hybrid approaches (21 mJ nad 19.5 mJ, respectively) remains closer to the one observed in MPR (17.9 mJ).

\smallskip
\noindent
\textbf{Relative Error (RE) of messages throughput.}
For this metric, we obtain the wireless topology formed at each broadcast session to get the number of neighbors per node.
%
With this ground truth and the number of received broadcast messages at each node, we show the distribution of the RE of received messages in form of a CDF in figure~\ref{plots:re-rcv-msgs}.
%
We observe that the throughput of receptions increases in one hybrid approach (dotted line in black) where controlled flooding is running in 50\% of the nodes at the sparse region.
%
The periodic exchange of beacons in MPR, which approximates surroundings, reduces the throughput in a deployed MANET (solid line in gray).
%
As expected, simple flooding shows the lowest performance (dotted line in gray). 

\smallskip
\noindent
\textbf{Reachability.}
Figure~\ref{plots:net-coverage} shows another perspective of reached nodes over all broadcast sessions.
%
Once again, we observe that a flooding approach in an sparse region increases the reachability of messages (solid line in black).
%
Up to 94\% of nodes receive all broadcast messages and 3\% of nodes miss up to 1\% of messages.
%
Notice that even in an static scenario we can not guarantee completely reachability due to the presence of collisions.
